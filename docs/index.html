Standard validation asks

  • Is AUC acceptable?
  • Is the model calibrated?
  • What is the approval rate?
  • Is portfolio bad rate controlled?

JANUS additionally asks

  • Can a declined applicant cross the threshold through presentation-sensitive changes?
  • Is genuine improvement much harder than cosmetic change?
  • Are truthful applicants being penalised?
  • Are some rejected because real capacity is poorly observed?
  • Does the model behave consistently across segments?

Conceptual example · not engine output

Two similar businesses, different outcomes

Same industry. Similar real sales. Similar operating history. Similar underlying repayment capacity. The difference is what the model is allowed to see.

Business A

Presents normal operating cash flow. Recorded balances match the running of the firm.

Likely treated as ordinary risk.

Business B

Receives a large manual capital injection shortly before assessment. Balance-derived features look stronger for a moment.

May look safer if the model treats a temporary balance as durable strength.

A capital injection is not inherently illegitimate. The integrity risk is mistaking a non-recurring presentation effect for sustainable repayment capacity.

  • Are truthful applicants being penalised?
  • Are we approving genuine capacity — or model-friendly presentation?

How much harder is it to become safer than to look safer?

Integrity Gap = effort to genuinely improve / effort to cosmetically change the decision

A ratio near 1 means presentation and genuine improvement are broadly aligned. A large ratio means it is substantially easier to look safer than to become safer. The ratio is only as credible as the lender-approved mutability and effort assumptions.

This is the median of per-applicant ratios — not the ratio of medians. Not interchangeable with attack-surface median cost. Observed engine result, not proof of fraud.

    Method

    How JANUS works

    1. Model + matured holdout data
    2. Feature dictionary + business context
    3. Agent proposes feature mutability
    4. Human confirms assumptions
    5. Deterministic engine runs the audit battery
    6. Agent interprets engine-produced evidence
    7. Human accepts or rejects findings
    8. Findings feed back into model development

    Language

    The LLM reads the dictionary, proposes how features can move, and explains findings. It never invents the audit statistics.

    Python engine

    Deterministic code calculates every number. Flip rates, costs, default comparisons, Route C. Each figure has a run ID.

    Humans

    A person signs the mutability table before search. A person accepts or rejects each finding. JANUS produces evidence. Credit and Risk decide.

    The LLM never invents the audit statistics.

    Governance

    Boundaries that stay on the critical path

    • JANUS does not make credit decisions.
    • Findings require model-owner and Credit/Risk review.
    • Detailed attack paths are restricted to defenders. They are never applicant guidance.
    • Do not upload PII. Synthetic or already-anonymised holdout only.
    • Only trusted model files should be loaded. Pickle/joblib can execute code.
    • The uploaded holdout is removed from memory after the run.
    • Results are hypotheses and audit evidence, not proof of fraud or causality.
    • Route C requires credible recorded-versus-verified evidence. On real data it is directional.
    • Synthetic reference results demonstrate the method; they do not establish real-world prevalence.
