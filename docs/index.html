JANUS investigates whether a lending model rewards genuine creditworthiness — or merely the ability to manipulate what it sees.

It is a red-team agent for credit models. It plans adversarial audits, follows evidence to the segments a model quietly harms, and returns a reproducible case for human model-risk review. Fairness is one branch. The question is simpler: does the model reward the thing it claims to measure?

The reference book is a model that passes standard review: AUC, features, no protected attributes, cutoff , approval. What it misses is below. Every figure traces to a run ID.

          Method

          the split is the compliance story

          The LLM decides what to investigate and what matters. It never produces a number. Every claim dereferences to a recorded run. A hallucinated statistic is structurally impossible, not merely discouraged.

          Elicit feature mutability → human gate. Run the mandatory battery. Form hypotheses from surprises. Design and run follow-up experiments. Judge materiality. Synthesise the memo from the investigation graph.

          Only numbers from run_audit.py, integrity_gap, and evidence_recourse appear here. Two attack-cost medians exist and are not interchangeable.

          Reproduce locally:

          pip install -e .
python -m janus.run_audit

          Demo data is synthetic. Generation logic and every planted mechanism are documented in janus/data_gen.py. No real applicant data is used.

          The battery says the model is gameable. The follow-up says gamed approvals are worse. The integrity gap says the honest path is two orders of magnitude more expensive. Then the recorded/true DTI split appears — and Route C is free. The people the model excludes could be approved for nothing.

          Janus does not make credit decisions. Attack recipes stay with the model owner. Recourse routes travel through the lender’s adverse-action process. Findings are diagnostic.
